Asset Management Automation

A nightly inventory sync that ties every device to its owner, its management status, and its warranty

1. The Challenge

When a staff member submits a help desk ticket, the first question a technician has to answer is which computer are we talking about? Without inventory data tied to the ticketing system, that meant guessing, asking the user, or searching other systems for the right machine before any real troubleshooting could start.

Warranty status had the same problem. Whether a device was still covered lived with the manufacturer, not with the ticket, so every hardware issue started with a separate lookup.

2. The Solution

I rebuilt the college's inventory tracking around HappyFox Assets, the same system the help desk already works in, and wrote an automation that keeps it current every night. It uses the college's own asset tags from Ellucian Colleague as the system of record and enriches each record from every other system that knows something about the device.

What the nightly sync does

  1. Pulls equipment from Colleague. Every equipment asset and its RCBC asset tag comes from the Ellucian Colleague ERP through the Informer API.
  2. Checks management status. Each device is looked up in MECM, Intune, and Jamf to confirm it is managed and has been given its standardized, imaged PC name, so technicians can search for the PC name directly in HappyFox.
  3. Pairs the asset with its owner. The asset's assigned steward is matched to the right staff contact in HappyFox, so the device appears on that person's contact record.
  4. Adds warranty dates. Dell, Lenovo, and Apple warranty APIs supply each device's coverage dates, which are written into HappyFox alongside the asset.
  5. Cleans up retired equipment. Systems that have been retired are removed automatically, so the inventory never drifts out of date.
Result: every ticket now arrives with the requester's assigned systems and their warranty status already on the contact. There's no more guessing which employee has which system.

3. Design Decisions

Delta-only processing

The sync only processes records that changed since the last run instead of pulling the full inventory every night, which keeps the job fast and light on every connected system.

One source of truth

RCBC's own asset tags in Colleague anchor every record. MECM, Intune, Jamf, and the warranty APIs add detail to that record rather than competing with it.

Data where the work happens

Technicians already live in HappyFox. Putting ownership, PC names, and warranty dates there means the answer is on screen before they start the ticket.

Windows and Mac together

Checking MECM, Intune, and Jamf in the same pass means Windows PCs and Macs are verified by the same process instead of separate, manual audits.
